1. OVERVIEW
----------------------------------------------------------------
Cintra is a small, line-oriented interpreted language implemented
in a single Python file (interpreter/cintra.py). It supports
bilingual keywords (English and Russian), variables, conditionals,
while loops, functions, lambdas, lists, modules, raw Python blocks,
and a prototype OOP system with inheritance.

The interpreter does NOT build an AST. Instead, function and class
bodies are transpiled to Python source and executed with exec().
Simple statements are translated one line at a time and executed
through eval()/exec() at runtime.

----------------------------------------------------------------
2. QUICK START
----------------------------------------------------------------
Requirements: Python 3.

Run:
    $ python cintra.py
    Enter file name: my_program.ctr

The interpreter reads the file line by line, executes it, and
prints one of:
    Program have been done with exit code 0.
    module on cintra included        (when run as a module)

Source files use the .ctr extension (not enforced by the parser).

3. ARCHITECTURE
----------------------------------------------------------------

3.1 TOKENIZER — better_than_split(line)
----------------------------------------------------------------
Purpose: split a raw source line into tokens WITHOUT using
str.split(). Scans character by character.

Token rules:
  - Consecutive letters form one token.
  - Consecutive digits form one token.
  - Letters and digits do NOT mix in a single token.
  - "_" and "." are appended to the current token regardless of
    the letter/digit classification. This is why "d.speak" is a
    single token, and why "my_var" stays intact.
  - All other characters ("=", "(", "+", ":", "/", etc.) become
    single-character tokens.
  - Whitespace separates tokens.

Examples:
    "i=1"                 -> ["i", "=", "1"]
    "var x = 10"          -> ["var", "x", "=", "10"]
    "d.speak"             -> ["d.speak"]
    "out \"hi world\""    -> ["out", "\"hi", "world\""]
    "// comment"          -> ["/", "/", "comment"]

Note: quotes are NOT special to the tokenizer. String literals
are reassembled later by joining tokens with spaces and passing
them to eval().

3.2 BODY TRANSPILER — translate_block(lines)
----------------------------------------------------------------
Purpose: convert a list of raw source lines (a function body or
a class body) into valid Python source code as a string.

Used by:
  - Function.end_of_init()   -> builds "def name(args): ..."
  - struct.end_of_init()     -> builds "class Name(Parent): ..."
  - Nested func inside func  -> recursive call

How it works:
  - Maintains an indent counter.
  - Reads each line, strips it, skips blank lines and lines that
    literally start with "//".
  - Dispatches on the first token:

    if / если         -> emits "if <cond>:"   (indent++)
    else / иначе      -> emits "else:"         (indent--)
    endif / конецесли -> indent--
    while / пока      -> emits "while <cond>:" (indent++)
    whileend / покаконец -> indent--
    func / функция    -> collects body until funcend, emits
                         "def name(self, args):" and RECURSIVELY
                         transpiles the body. self is prepended
                         automatically.
    funcend           -> (ignored; loop handles it)
    everything else   -> passed to parser_of_expressions()

  - "&&" and "||" are translated to "and" / "or".
  - A trailing ":" on if/while conditions is stripped.

3.3 EXPRESSION PARSER — parser_of_expressions(line)
----------------------------------------------------------------
Purpose: translate a single logical line into a Python expression
or statement string. Used both inside translate_block (for function
bodies) and by understand_line at runtime.

Handled keywords:

    out / вывести            -> "print(<joined tokens>)"
    in / ввести              -> "<var> = input()"
    out_type / вывести_тип   -> "print(<type(line[1])>)"  [BROKEN,
                                 see Section 6]
    call / вызвать           -> "<name>(<args>)"
    return / вернуть         -> "return <recursive parse>"
    var / let / переменная   -> "<name> = <value>"
                                (assumes "var NAME = VALUE")
    if / если                -> "if <cond>"   (no colon)
    push / добавить          -> "<list>.append(eval(<value>))"
                                (evaluated at transpile time — bug)
    anything else            -> " ".join(tokens)  (raw Python)

3.4 RUNTIME EXECUTOR — understand_line(line, line_no)
----------------------------------------------------------------
Purpose: execute a single tokenized line at runtime.

Handled keywords and their effect:

    if / если        -> eval condition; taken=1 or skip=1
    else / иначе     -> if taken==1, set skip=1
    endif/конецесли  -> taken = 0
    out / вывести    -> print(eval(parser_of_expressions(...)))
    in / ввести      -> read input; convert to existing type if
                        the variable already exists
    include / подключить -> importlib.import_module(name)
    out_type/вывести_тип -> print(type(eval(<expr>)))
    lambda / лямбда  -> define a function via exec()
    call / вызвать   -> stack[name]() or stack[name](*args)
    push / добавить  -> stack[list].append(eval(token))
    var / let / переменная -> stack[name] = eval(rest)
    name OP expr     -> direct assignment using =, +=, -=, *=,
                        /=, %=, **=, //=
    fallback         -> if is_python is True: exec(line);
                        otherwise print "SYNTAX ERROR on line N"

3.5 BLOCK RUNNER — run_block(body, body_nums)
----------------------------------------------------------------
Executes a list of already-tokenized lines. Used to execute the
body of a while loop, because the loop body must be re-run each
iteration. Handles skip/taken logic, nested while loops, and
dispatches individual lines to understand_line().

3.6 MAIN LOOP — run_code(file_name)
----------------------------------------------------------------
Reads the file line by line. For each line:
  1. Tokenizes with better_than_split().
  2. If skip > 0, tracks nested if/while/else to know when to
     resume execution.
  3. Otherwise dispatches:
     - lambda, call      -> understand_line()
     - cintrafile / файлцинтра -> recursive run_code() in module
                                   mode (sets is_module flag)
     - func / функция    -> read body until funcend, build
                            Function object, call end_of_init()
     - struct/class/...  -> read body until the corresponding end
                            keyword, build struct object, call
                            end_of_init()
     - push / добавить   -> immediate append to a list
     - pythonblock / блокпитона -> set is_python = True
     - pythonend / конецпитона  -> set is_python = False
     - while / пока      -> read body until whileend, then run
                            the loop with run_block()
     - everything else   -> understand_line()

Note: when a line is NOT one of else/if/while/func, trailing ";"
is stripped and the line is re-tokenized. This allows statements
to end with ";" without breaking.

3.7 CLASS Function
----------------------------------------------------------------
Represents a user-defined function.

  Function(name, args)   — args may be a string ("a, b") or a
                           list of names
  .add_line(raw)         — accumulate raw body lines
  .end_of_init()         — transpile body with translate_block,
                           then exec("def name(args): ...", stack)

Functions defined at top level receive exactly the argument list
from the header. Functions defined INSIDE another function or
inside a class receive "self" prepended by translate_block.

3.8 CLASS struct
----------------------------------------------------------------
Represents a class declaration.

  struct(name, parent)   — parent is "" if no inheritance
  .add_line(raw)         — accumulate body lines
  .end_of_init()         — transpile body, then
                           exec("class Name(Parent): ...", stack)

The resulting Python class is stored in the global stack dict.

----------------------------------------------------------------
4. LANGUAGE REFERENCE
----------------------------------------------------------------

4.1 COMMENTS
----------------------------------------------------------------
Lines whose STRIPPED form starts with "//" are ignored by
translate_block (inside function/class bodies).

At the TOP LEVEL (inside run_code), "// comment" is tokenized
to ["/", "/", "comment"], which does NOT start with "//" after
joining tokens, so top-level comments fall through and may
trigger "SYNTAX ERROR on line N". Use comments only inside
function/class bodies, or accept the error message.

4.2 VARIABLES & ASSIGNMENT
----------------------------------------------------------------
Declare:
    var x = 10
    let name = "Alice"
    переменная pi = 3.14

The parser expects the exact shape "var NAME = VALUE".
The keyword, name and "=" are all required.

Direct assignment without a keyword also works:
    x = 10
    x += 1

All variables live in one global dict called "stack". There is
no block scoping, no local scope, no closures beyond Python's
own function semantics.

4.3 OPERATORS
----------------------------------------------------------------
Logical:     && (-> "and"), || (-> "or")
Comparison:  ==, !=, <, >, <=, >=
Arithmetic:  +, -, *, /, //, %, **

Operator precedence follows Python because expressions are
evaluated by eval().

4.4 INPUT / OUTPUT
----------------------------------------------------------------
Print:
    out "Hello, world!"
    вывести 42
    out x + y

The argument to out is passed to eval() at runtime, so string
literals must include quotes. Unquoted bare words are treated
as variable names.

Read input:
    in name
    ввести age

If the variable already exists in the stack, the input string
is converted to the same type (int, float, etc.). Otherwise,
it is stored as a string. Conversion failures are caught and
reported as "BAD INPUT on line N".

4.5 CONDITIONALS
----------------------------------------------------------------
    if x > 10
        out "big"
    else
        out "small"
    endif

Russian:
    если x > 10
        вывести "большое"
    иначе
        вывести "маленькое"
    конецесли

A trailing ":" after the condition is optional and stripped.
Nested if/else works. The else clause binds to the currently
active if (via global "taken"/"skip" flags), which is fragile
in deeply nested cases.

4.6 LOOPS
----------------------------------------------------------------
Only while loops:
    var i = 0
    while i < 5
        out i
        i += 1
    whileend

Russian:
    пока i < 5
        вывести i
        i += 1
    покаконец

Nested loops are supported. Each while must be matched with
whileend. The body is collected until the matching whileend
(tracking nesting depth), then executed with run_block().

4.7 FUNCTIONS
----------------------------------------------------------------
Definition:
    func greet(name)
        out "Hello, " + name
    funcend
    call greet Alice

or without parentheses:
    func add a b
        return a + b
    funcend
    call add 2 3

Russian:
    функция add(a, b)
        вернуть a + b
    конецфункции

Call syntax (no commas, space-separated):
    call name
    call name arg1 arg2

Arguments are evaluated individually via eval(). The function is
looked up by name in the global stack dict.

Note: functions defined INSIDE another function or inside a class
receive "self" prepended to their argument list by
translate_block. Top-level functions do not.

Return:
    return value
    вернуть value

4.8 LAMBDAS
----------------------------------------------------------------
Syntax:
    lambda name arg1 arg2 : expression
    лямбда имя арг1 арг2 : выражение

Example:
    lambda double x : x * 2
    call double 5

The interpreter builds a Python "def name(args): <expression>"
and execs it. Because no return is inserted automatically, the
lambda returns None UNLESS you write an explicit return:

    lambda double x : return x * 2

Lambdas must be defined before use. This feature is marked
"beta" in the source.

4.9 LISTS
----------------------------------------------------------------
    var items = []
    push items 10
    push items 20
    out items

push appends a single evaluated token to the list. The expression
after push may only be a single token (the interpreter evaluates
only line[2]); "push items 1 + 2" will append only 1.

4.10 OOP — struct / class
----------------------------------------------------------------
Cintra supports a prototype class system.

Declaration:
    struct Point
        // methods
    structend

Russian:
    класс Animal
        // методы
    конецкласса

Also accepted end keywords: structend, classend, конецструктуры,
конецкласса.

Inheritance: a second word after the class name is the parent.

    class Dog Animal
        func speak()
            out "Woof"
        funcend
    classend

Methods are functions declared inside the class body. The
transpiler prepends "self" to their argument list automatically,
so "func speak()" becomes Python "def speak(self):".

Instantiate with normal Python syntax inside Cintra:
    var p = Point()

Call methods by evaluating a Python attribute access:
    out d.speak()

Note: the "call" keyword does NOT support dotted names. "call
d.speak" would try to find the key "d.speak" in the stack dict
and fail. Use "out" or a Python block if you need to call a
method via call.

4.11 MODULES
----------------------------------------------------------------
Import a Python module:
    include math
    подключить math

This calls importlib.import_module(name). The module is NOT
bound into the Cintra stack, so you cannot call its functions
directly by name. It must be used via raw Python code or a
pythonblock.

Run another Cintra file:
    cintrafile other_module
    файлцинтра другой_модуль

The file name must NOT include an extension. The target runs in
module mode (is_module = True) and prints
"module on cintra included" instead of the normal exit message.

4.12 PYTHON BLOCKS
----------------------------------------------------------------
    pythonblock
        // raw Python lines here
    pythonend

Inside a block, lines are executed directly via exec() only when
understand_line reaches the fallback branch. is_python is a
global flag; the interpreter prints "Python block running..."
and "Python block ended" for feedback.

6. KNOWN LIMITATIONS & BUGS
----------------------------------------------------------------
These are accurate as of the current interpreter source.

1.  Single global scope. All variables live in one dict "stack".
    No block scoping, no local variables.

2.  Transpilation via exec/eval. Parsing happens twice (Cintra ->
    Python string -> Python AST). Tracebacks show generated Python
    lines, not original Cintra lines. Any Python expression can be
    evaluated, including arbitrary code.

3.  No AST. Line-by-line translation limits complex syntax,
    operator overloading, and static analysis.

4.  else binds to a single if scope. Nested if/else inside loops
    works for simple cases, but the global "taken"/"skip" flags
    can misbehave with complex nesting.

5.  Lambdas do not return a value unless you write "return"
    explicitly:
        lambda double x : x * 2            -> returns None
        lambda double x : return x * 2     -> returns x * 2

6.  Input type conversion only for existing variables. New
    variables receive raw strings.

7.  Top-level functions do not receive "self"; nested functions
    and methods do. This asymmetry can be confusing.

8.  Comments outside function/class bodies fall through the
    tokenizer and print "SYNTAX ERROR on line N".

9.  out_type in parser_of_expressions is broken — it emits
    "print(<class 'str'>)", which is invalid Python. The working
    out_type is handled directly by understand_line.

10. push only accepts a single-token expression. "push items 1 + 2"
    appends 1.

11. include imports the module but does not bind it to the stack.
    Its functions cannot be called by name from Cintra.

12. call does not support dotted names. Methods must be invoked
    through an expression evaluated by "out" or via pythonblock.

13. Error messages are basic ("BAD CONDITION", "SYNTAX ERROR",
    "BAD KEYWORDS"). No column, no traceback, no suggestions.

14. No standard library, no package manager, no tests in the repo.

7. COMPLETE EXAMPLES

FIZZBUZZ
--------
var i = 1
while i <= 20
    if i % 15 == 0
        out "FizzBuzz"
    else
    if i % 3 == 0
        out "Fizz"
    else
    if i % 5 == 0
        out "Buzz"
    else
        out i
    endif
    endif
    endif
    i += 1
whileend

FUNCTION WITH RETURN
--------------------
func square(x)
    return x * x
funcend

var n = 7
out square n

LAMBDA WITH EXPLICIT RETURN
---------------------------
lambda triple x : return x * 3
call triple 5

LIST
----
var items = []
push items 10
push items 20
out items

CLASS WITH INHERITANCE
----------------------
class Animal
    func speak()
        out "..."
    funcend
classend

class Dog Animal
    func speak()
        out "Woof"
    funcend
classend

var d = Dog()
out d.speak()
